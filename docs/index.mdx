# Cloud Native Mail Service (CNMS)

CNMS is a Kubernetes operator by Rocket Pad Platforms that runs and manages
email servers on Kubernetes: **Postfix** (SMTP in/out, relay), **Rspamd**
with **Valkey** (spam filtering, DKIM signing, SPF/DMARC checks, rate
limits), and **Dovecot** (IMAP, LMTP, SASL authentication).

The operator is a control plane, not an MTA: it renders configuration for
proven software and manages its lifecycle. Control plane and data plane are
separate — if the operator is down, mail keeps flowing.

**Status:** pre-v1 — API version `cnms.rpp.gmbh/v1alpha1`, subject to
change. Upgrade notes are published for every release.

## What CNMS gives you

- **Mail servers as custom resources.** Declare a `MailServer` and CNMS runs
  the full data plane — Postfix, Rspamd, Valkey and Dovecot — with
  production-grade defaults: TLS, rate limits, DKIM signing, recipient
  validation.
- **Reputation isolation.** Every `MailServer` owns its workloads, queues,
  sending addresses, DKIM keys and HELO names, so several mail systems on
  one cluster never share sender reputation.
- **Mail is never lost to a component outage.** Filtering or lookup
  failures delay mail (4xx and queueing) — they never reject it or send it
  unsigned.
- **Users stay outside the operator.** Mailboxes and accounts come from an
  external directory (LDAP or SQL); CNMS only configures Postfix and Dovecot
  to query it.
