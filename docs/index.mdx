# Cloud Native Mail Service (CNMS)

CNMS is a Kubernetes operator by Rocket Pad Platforms that runs and manages
email servers on Kubernetes: **Postfix** (SMTP in/out, relay), **Rspamd**
with **Valkey** (spam filtering, SPF/DMARC checks, rate limits, DKIM
signing), and **Dovecot** (IMAP, LMTP, SASL authentication).

The operator is a control plane, not an MTA: it renders configuration for
proven software and manages its lifecycle. Control plane and data plane are
separate — if the operator is down, mail keeps flowing.

**Status:** pre-v1 — API version `cnms.rpp.gmbh/v1alpha1`, subject to
change. Upgrade notes are published for every release.

:::danger
Mail of authenticated senders is signed with the DKIM keys of the
`MailDomain`; a served domain without a usable key defers its outbound
mail (`451 4.7.1`) instead of sending it unsigned. Users come from a
`MailDirectory` (LDAP or PostgreSQL), from `MailUser`s, or from the static
test users (a test feature); a server has one of the three. Do not send production mail from
a CNMS server yet.
:::

## What CNMS gives you

- **Mail servers as custom resources.** Declare a `MailServer` and CNMS runs
  the full data plane — Postfix, Rspamd, Valkey and Dovecot — with
  production-grade defaults: TLS, rate limits and recipient validation
  (against the static test users until the directory phase), and DKIM
  signing with the keys of the `MailDomain`.
- **Reputation isolation.** Every `MailServer` owns its workloads, queues,
  sending addresses, DKIM keys and HELO names, so several mail systems on
  one cluster never share sender reputation. Workloads, queues, Rspamd,
  Valkey and DKIM keys are isolated today; sending addresses follow in
  Phase 7.
- **Mail is never lost to a component outage.** Filtering or lookup
  failures delay mail (4xx and queueing) — they never reject it.
- **Mail is never sent unsigned.** Mail of authenticated senders and
  Postfix's own non-SMTP mail leaves signed or not at all: a domain
  without a usable key defers its outbound mail until it has one.
- **Users stay outside the operator by default.** Mailboxes and accounts come
  from an external directory (LDAP or SQL); CNMS only configures Postfix and
  Dovecot to query it. Environments without a directory service use
  operator-managed `MailUser` accounts
  ([ADR 0008](decisions/0008-user-sources-and-service-accounts.md)).
